# Kickoff interview, 2026-09-24

Spoken interview after the research in `RESEARCH.md`. Answers are condensed from the transcript.

**Q: What is the concrete trigger for Primavista? What hurts most about CKEditor in Sulu?**
A mix of everything. The main trigger is the license, which gets stricter and causes more and more problems. Styling and extensibility are fine as they are, keep that approach. Bundle size has become unbearable. The goal for today is a prototype to see how well it could work.

**Q: ProseMirror, Lexical, or something own?**
No preference. Smaller is better as long as it meets Sulu's needs. Something own is probably not feasible. After hearing that Lexical has an official table package: use Lexical, the smaller package. Collaboration is not needed. If Lexical does not suffice it can be swapped later. Saving about 80 KB would be ideal.

**Q: Storage format, HTML or JSON?**
HTML is perfect. JSON is generated internally only. HTML in, HTML out. No JSON storage.

**Q: How important is true frontend style fidelity inside the editor?**
Absolutely unimportant. CKEditor cannot do it either and that is enough for Sulu because of the preview. Keep it like CKEditor.

**Q: Minimum feature set for the prototype?**
Bold, italic, headings, lists, tables, internal links to pages and media must work. The important part is the plugin system so Sulu can add its plugins, plus basic table functionality.

**Q: License and order?**
Fully MIT, no license in front of it. Build Symfony UX first, but the React application in parallel. Interesting demo: one Symfony application that includes the bundle via Symfony UX and also renders the Sulu React component, both on one page, one below the other.

**Q: GitHub organization and anything missing?**
No worries about the GitHub org now. The name may change anyway. It runs locally for the moment.

**Wrap-up:** Summary confirmed without corrections.
